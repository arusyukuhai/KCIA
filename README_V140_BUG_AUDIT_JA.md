# KCIA v140 — v139バグ監査・通信費用モデルの安全化

この版は、実機で動作したv139のWAN P2Pや署名プロトコルを変更せず、**ローカルの通信間隔制御とGUI起動安全性**を改修したものです。

## 監査で修正した問題

1. **オフライン時の架空通信費用**：以前の `seal_if_needed()` は接続ピア数を最低1としていました。実際に送信対象がいない間にも巨大な署名付きLoHA更新（例：158MiB）を1件送ったとみなし、通信費用の推定器を更新していました。`live_push_recipients()`で認証済み・同期済み・生存確認済みの相手を数え、0件ならバンディットの観測を無効化します。オフライン中も学習・署名ジャーナル更新は通常どおり進みます。
2. **接続ピア数とPush先数の取り違え**：実際の `selective_push_targets()` は `--push-fanout`（既定2）までしか大型更新を即時Pushしないのに、v139の見積もりは接続している全ピア数を掛けていました。v140は最大ファンアウトまでの送信先数のみを見積もります。実測Push/Repairの累積バイト数は別途参照するため、遅延した転送は精密なイベント別課金ではありません。
3. **GUI二重起動時の設定副作用**：起動中のチェックより前に、学習方式のsidecar・ピア用データセット・起動ポリシーを書き込む可能性がありました。ワーカー起動中を最初に検出して例外にすることで、設定ファイルを書き換えずに拒否します。既存の直前チェックも保持します。
4. **補助キャッシュの掃除失敗による学習停止**：バンディット統計のatomic writeに失敗した後、一時ファイルのunlinkも失敗すると例外が学習エンジンへ流れ得ました。キャッシュはベストエフォートとし、消去失敗も学習を中断しません。
5. **無効な観測の扱い**：変更したバンディットの `observe()` は0ピアを無効観測として処理します。負の送信先数、真偽値、整数でない値、8を超える値は従来どおり拒否。指定した候補外の学習ステップ数も観測を採用しません。

## 使い方

- v139からの差分を現在のリポジトリへ適用するか、v140の完全版を展開する。GUI・学習プロセスを完全停止させてから適用。
- 既存のルーム、署名鍵、`.kcia-gui`、`wan_state`、SQLiteジャーナル、チェックポイントは**削除しない**。
- 起動: `python -m patchlib.cli gui`。
- WAN既定: `wss://signal.kcia.tech/ws`（旧来の接続可能な経路を維持）。
- 学習間隔の実際の改善を測るには同じデータセット・学習トークン数でLoss、`publish_steps`、`push_mib`、`repair_mib`を比較する。

## 検証と限界

新規回帰テスト `tests/test_v140_safety.py` は、オフライン15イベントで架空の通信費用や学習履歴が生まれないこと、認証済みピアのPushファンアウトの範囲、GUI二重起動で副作用が出ないこと、キャッシュ一時ファイル削除失敗時も学習を継続できることを検査します。

既存テストに加えてGUI・バンディット・WAN・スナップショット関連の回帰試験を実行しました。ただし実環境のMac/Colab/ConoHaでの長時間検証は、このアーティファクト構築環境では行っていません。「未知のバグがゼロ」とは保証しません。

**変更していないもの**：署名・鍵・Genesis・ルームマニフェスト・イベントのオンワイヤ形式、PPO/SFT/PTの学習アルゴリズム、TURNシグナリングとcoturn構成。
