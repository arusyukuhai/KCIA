# KCIA v116 — 真のクライアント別LoHAランク / フレームレスGUI

## 変更点

* LoHAの各ピアが `--local-loha-rank auto` または `8` 等で、**実際に小さな形状のLoHA行列**を割り当てます。
* 勾配、AdamWのmoment、アンカーバッファ、出力.fpatch、署名イベント、WebRTC Gossipが物理ランク分だけ小さくなります。通信中のパディングはありません。
* ルーム共通の `rank` は「最大rank」。すべての参加ピアでモデル・対象レイヤー・共有ランクは一致したまま、送信者固有の `rank` を各signed targetに含めます。
* 受信側はtarget実rank・shape・layout・署名を検査後、**送信者ランクで**正規化したLoHA重み差分を生成してFedSum加算します。LoHAの因子自体は平均しません。
* 古いfull-rankイベントも読み込み可能です。ただし、**v115以前のクライアントは小ランクの新イベントを拒否**するため、参加クライアントは同時にv116に更新してください。
* ランクは`<journal>.physical-rank.json`へ保存し、再開時は復元。既存ジャーナルは安全のため従来full rankを保持します。既存データを消去しません。
* 端末の利用可能なメモリ・推定Adapter+Grad+AdamW容量、およびCPU/MPS/CUDAの計算能力上限を使いrankを選択します。CPU自動上限8、MPS上限16、CUDAはルーム上限です。モデル本体・活性化が収まる保証ではありません。
* `--local-loha-rank` は学習開始前にのみ決定します。ランク変更には新しいローカルピア/ジャーナルが必要で、既存未送信更新の切り捨ては行いません。
* GUIで新規作成するLoHAルームは最大rank32を標準値とし、作成者が低性能でもColab側のrank選択を妨げません。既存ルームの上限は変更しません。
* 低ランクにした分、更新の表現力は小さくなり、Dense fallbackやwide LoRA対象の容量は共通仕様のままで削減されません。
* OSの標準タイトルバーを非表示にしたpywebviewウィンドウ、専用ドラッグ領域と最小化・最大化・閉じるボタンを搭載しています。

## 注意

本変更は従来プロトコルと混在させないでください。実際のVPS / Colab / Mac混成環境、Apple MPS / CUDA / WebRTCでの相互接続は別途検証が必要です。

## 形状・Optimizer・送信バイト数の検証例

128×128の単一LoHA対象行列、共通最大rank32、float16送信、AdamW 1 step後の測定（CPU）。

| ピア実rank | trainable factor要素数 | AdamW moment要素数 | `.fpatch`バイト数 |
| ---: | ---: | ---: | ---: |
| 4 | 2,048 | 4,096 | 4,730 |
| 8 | 4,096 | 8,192 | 8,826 |
| 16 | 8,192 | 16,384 | 17,027 |
| 32 | 16,384 | 32,768 | 33,371 |

上記は単層の測定であり、実モデルではwide LoRA・dense対象・イベント署名ヘッダー等の固定費が加わります。`fpatch`サイズはランク縮小時にpaddingされません。
