# Kagami v90 — 通常GUIでの1・2・3ピア認証済み世代移行

## 今回の修正

通常GUIの**新規ルーム**において、最初の認証済み委員会を必ず3台で組む制約を撤廃しました。GUIの操作は従来どおりです。

| 初回に固定された委員会 | 世代認証に必要な署名 | 意味 |
| --- | --- | --- |
| 1台 | 1/1 | 自分自身の署名でcertified checkpointを作成。これは**自己認証**であり、第三者による検証や耐故障性はない |
| 2台 | 2/2 | 両方の独立した鍵が検証・署名するまで世代確定しない |
| 3台 | 2/3 | 従来と同じ。2台の署名で確定可能 |

初回の所有者署名付き委員会は、**認証済みの接続状態が安定してから1回だけ**確定します。通常GUIでは、3台が認証できていれば直ちに、1〜2台では起動から最低20秒、最後に認証済みメンバー集合が変化してから最低12秒待ちます。初期接続が遅い場合、2台を想定したルームが先に単独委員会として確定することもあります。最初のルーム作成時は、共同で署名させたいピアをすぐ接続してください。

**固定された委員会の人数を、オンライン台数に合わせて後から変更する処理ではありません。** たとえば、2台委員会の片方が切断しても2/2のままです。固定済み3台委員会の1台だけが残った場合、1/1へ格下げしません。自動的な安全なメンバー交代には、別途証明書付きの委員会再構成プロトコルが必要です。この版には含まれません。新規に接続した4台目以降も、初回署名済み委員会の投票権を勝手に付与されません。

旧v88の**署名済み3台委員会はそのまま読み込む**ため、既存の世代認証ルールは変えません。新しい1〜2台委員会には `kagami-automatic-committee-v90` の署名ドメインを使用します。**同一ルームに接続する全ピアをv90へ更新**してください。旧v88/v89端末は少数委員会ロスターを受け入れません。

## 統合weight・ジャーナルの扱い

- 既存のv57/v58 model export、Merkle frontier、署名投票、carry、certified checkpoint、世代切替、GCを利用します。
- 1/1でも、署名されたイベントの検証、ローカルweight/optimizerの確定、古いjournalの未反映更新のcarry保存・writer停止・安全なGCという条件は省略しません。
- 2/2の場合は**両者の同意・検証**が必要です。片側が不在でディスク上限に近づいたら、既存のジャーナル圧力制御によりローカル学習を安全に一時停止します。
- 3台以上のルームでは、初回委員会は最大3台を選択し、従来の2/3方式です。
- `journal-status` は署名済み委員会サイズ、必要なquorumを表示します。ただし状態確認は**読み取り専用の参考情報**で、内容自体の署名認証を代行しません。

## 使用方法

```
python kagami.py                   # GUIからNEW MODELで新しいルームを作成
python kagami.py journal-status --journal /path/to/events.sqlite3
```

**過去に4GiBで停止した既存ジャーナルを、このZIPの導入だけで縮小することはできません。** まず `journal-status` で既存ルームに固定委員会があるか調べてください。古い署名ログを手動削除しないでください。


少数委員会の暗号学的署名投票、認証済みチェックポイントのハッシュ検証、旧3台委員会の互換性、署名済み委員会の改変拒否、2台委員会の一時切断時の定足数維持、ジャーナルGCの既存の回帰テストを確認しています。

**実機macOS/WebRTCでの1〜2ピア長時間学習と、4GiBに達した実データを用いた自動世代移行・GCの完遂は未検証です。** ディスクの必要量や同期障害などにより移行が遅れる場合は、データ保護のため停止します。

### 2台でのチェックポイント転送（重要）

v89のままだと、一部の転送経路が「確定済み証明書を見てからweightを送信」という順番で、相手がweightを検証して2/2の2つ目の署名を出すまで進めない問題がありました。v90では、**認証済みの候補endorsement＋フェンス済みexport receiptの両方**が揃った場合に限り、チェックポイントを**投票前の検証用データ**としてダウンロードできます。この段階でweightの実運用採用やGCはしません。相手がshardとMerkle cutを完全検証した後でのみ署名し、認証済みクォーラムが確定した場合だけ世代を進めます。

この変更には `patchlib/pending_snapshot_v90.py` と `patchlib/live_generation_transport.py` / `patchlib/elasticnet.py` の転送経路修正が含まれます。受信した候補を実際のweightとして使うことはありません。
