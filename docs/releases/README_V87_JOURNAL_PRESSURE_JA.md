# v87 Durable update log quota / 世代切替前倒し

**エラー原因:** `durable update log is full` は `--max-journal-gb`（GUI: Journal GiB、既定4GiB）による人工的な**署名付きパッチの累積容量制限**。OSの `No space left on device` と同一ではありません。

この更新では次を修正しています。

- 単発・バッチ双方のイベント追記時、使用量・追記予定量・設定上限をエラーに含めます。
- `--generation-v1-committee` と `--generation-v2-trainer` を明示設定したルームでは、通常の更新回数トリガーに加え、ジャーナル使用率が約65%を超えると**認証済み世代のチェックポイント生成を前倒し**します。大量の受信イベントにより、自分が更新を発行していない場合も対象になります。重い再試行は容量増分128MiB以下の間隔に制限しています。
- **未認証のジャーナル削除はしません。** 認証済み切替・互換性維持が成立するまで既存の署名履歴を保持します。

## 今すぐ復旧したいとき

1. `python kagami.py disk-report --journal /path/to/events.sqlite3` で空き容量・保存領域を確認。
2. 実際の空きが十分あり、一時的に継続する場合のみ、GUIの **Journal GiB** を4→8などへ変更してから再起動。CLIは `--max-journal-gb 8` を指定。**物理容量が足りないなら上限増加は禁止。** これは暫定対策であり古い履歴は減りません。
3. 学習を捨ててもよいデバッグルームなら、**全プロセス停止後** `python kagami.py reset-local-data --yes`（CLI既定領域も対象にするなら `--include-cli-defaults` を追加）を実行し、**新しいルーム**で開始。学習済みデータ・ローカル鍵を失うためバックアップを推奨。
4. 署名履歴を消して学習成果を保持するには、委員会をピン留めした認証済み世代移行の成功が必要です。単に最新weightを保存するだけでは不十分です。

## 制約

- 通常GUIでは認証済み世代移行は**自動的に有効になりません**。この更新はGUIを無断で単独委員会に変更しません。
- 前倒しエクスポートは証明成立を保証しません。空き容量・ピアの参加・投票・checkpoint検証に失敗すれば上限で安全停止します。
- 現役ジャーナルの無損失・無条件・常時自動削除は未実装です。これを実装済みと見なさないでください。
