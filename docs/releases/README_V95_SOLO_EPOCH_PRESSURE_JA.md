# Kagami v95 — 単独ピアの認証済み世代移行が80%で止まる問題への対策

## 問題

v89以降の自動世代移行では、署名付きジャーナルが80%になるとローカル学習を一時停止し、チェックポイント作成と認証済み世代切替を優先する。

従来の `maybe_propose_compact_epoch()` は、チェックポイント作成を**試行した時点**で `compact_last_export` / `compact_last_export_bytes` を更新していた。`capture()`、背景エクスポート、ハッシュ検査等が失敗すると、その時点からジャーナルのサイズと更新連番が増えなければ新たな試行条件が成立しない。このため、特に単独ピアで `V89 EPOCH PRESSURE HOLD` が繰り返されることがあった。

**今回のユーザー環境にある具体的な失敗原因が、ログだけから確定したわけではない。** v95ではこの停止条件を解消し、詳しい段階診断を追加した。

## 変更点

- チェックポイントのキャプチャ／背景エクスポート失敗後、ローカル更新数・署名ログ容量が変わらなくても5〜120秒の有界バックオフで再試行する。
- エクスポートジョブが実行中なら並列に二重起動しない。
- 途中クラッシュで不完全な候補だけ永続化された場合は、**同一候補**を復元できる場合にのみ再生成／補完する。異なる候補を同じ世代で認証することは拒否する。
- 1/1固定委員会の候補生成 → ローカル検証 → 本人署名 → 証明書確定を、ネットワーク不使用の小型weightで回帰テストする。
- `V95 EPOCH PRESSURE HOLD` にexport実行状況・エラー内容・再試行待ちなどの段階を表示する。
- `journal-status` に署名付きエクスポート受領証・Merkleページ・署名済み候補の件数と、単独ピアの停滞段階を追加する。
- ジャーナルパスにスペースがあるmacOSでコピペしやすいよう、表示コマンドのパスを引用符付きにする。

## 使い方

GUIを終了し、元のKagamiディレクトリと学習データを別途バックアップした後、本パッケージのコードを置き換えてGUIを再起動する。**既存のweight、署名ジャーナル、識別鍵、carryアーカイブは削除しない。** `reset-local-data` は実行しない。

状態確認（読み取り専用）:

```bash
python kagami.py journal-status --journal '/Users/al/Library/Application Support/Kagami/.fedpara-gui/rooms/LI7JzPNv6TrI-BHpHMMSzR6CpkYxUyfI/peers/peer-b3c84c73915727e9/events.sqlite3'
```

通常GUIは `python kagami.py` で起動。

## 重要な制限

- 1/1委員会における「1人で署名確定」は、その委員会が**正しく固定され、署名鍵とチェックポイントが検証できる**場合のみ成立する。ログ圧迫だけで世代を切り替えることはない。
- 2/2委員会が片方の切断時に1/1へ縮退することはない。
- 途中失敗の原因がディスクの実容量不足なら、再試行だけでは解決しない。`disk-report` で物理ディスク空き容量を確認する。
- ソースのみのテスト（109件成功）であり、依頼者の既存数GiBジャーナルや実機macOSでの長時間運用は未検証。
- `V95`で保留が続く場合、最後に表示される `stage=` と `journal-status` の全出力を使って残った停止条件を確認する。
