# KCIA v88: 通常GUI向け認証済み世代移行の自動化

本版は、v87のジャーナル逼迫対策を引き継ぎ、新しくGUIから作成したルームで、認証済み世代移行と旧ジャーナルの安全な削除を自動化します。

## 通常の操作

1. 既存の学習/GUIを停止し、データをバックアップして本版へ切り替える。
2. GUIの **NEW MODEL** から**新規ルーム**を作成して学習開始する。GUIでの追加設定は不要。
3. ルームの作成者を含む **独立した3つの署名付きピア** を接続する。ルーム作成者が参加ピアの公開鍵から一度だけ委員会を選び、所有者署名を付けて全ピアへ配布する。各ピアは署名・ルーム/初期モデルとの結合・公開鍵由来のIDを検証して固定する。
4. 委員会の**実際の異なる2ピア以上**が検証・署名し、認証済み世代チェックポイントが確定すると、既存のv57/v58学習世代切替を用いてweight・Optimizer・P2P通信を新世代に切り替える。目標は通常128回のローカル公開更新ごと、またはジャーナルが上限の約65%に近づいた場合。
5. 切替後、旧世代ジャーナルの停止・確定済みチェックポイント・署名イベントの認証済みcut・未反映更新のcarry archiveへの完全保存をチェックし、自動削除する。途中クラッシュ時は新世代の再起動検証を通してから削除を再試行する。

## 自動化の安全境界

- ルームの**既存マニフェストに勝手に所有者公開鍵を後付けしない**。既存ルームは従来の動作のまま。自動化するには**新しいルームを作り、正しい初期weightから開始**する。既存ルームのジャーナルやルームIDを流用・上書きしない。
- 初めから3ピア未満、固定委員会の2人以上がオフライン、あるいは独立した検証署名が得られない場合は、認証済み世代移行は**成立しない**。勝手に票を水増ししたり、既存の署名済みイベントを消すことはない。学習が上限に達すると安全停止する。これは仕様上の安全条件。
- 3人が揃っても、証明/チェックポイントの受信・認証・容量に問題がある場合は移行は延期される。チェックポイントを作る**実ディスク空き容量**が必要。単独ピア向け無条件ログ削除は実装しない。
- 一度所有者署名付き委員会が確定したら、その構成を勝手に入れ替えない。長期離脱への**認証付き委員会再構成**は本版の対象外。
- 新世代への切替後も、古い世代でまだ適用されていない真正な署名更新はcarry archiveに残し、追加到着を許容する。再起動で初期carryの改変を検出する。旧世代のソースSQLite・`.fplog` と当該ローカルfast-resumeキャッシュのみが削除対象。
- 新世代の現在のジャーナル・まだ必要なcarry archive・認証済みチェックポイントの実体は削除しない。これらは別途ディスク容量が必要で、**全ストレージ量が永久に一定になるわけではない**。

## CLI の関係

GUIによる新規ルームでは自動的に `--generation-auto-v88` を付けて起動する。通常はユーザーが指定する必要はない。手動CLIで指定する場合は、同じルームの不変な `generation.owner` を含む署名付きルームマニフェストが必要。

ログ例： `V88 AUTO GENERATION COMMITTEE owner-signed`、`COMPACT EPOCH CANDIDATE`、`LIVE EPOCH ACTIVATED`、`V88 COMPACT GC retired old signed writer`。

## データの扱い・互換性

この版はv87の機能を維持するが、**既存データを自動移行するツールではない**。特に現役のログが満杯の古いルームを「自動世代移行済み」と偽装しない。既存データはバックアップした上で、旧ルームで別の既知の安全な退避/再開手順を使う。

実装: `patchlib/auto_committee_v88.py`、`patchlib/compact_journal_gc_v88.py`、`patchlib/elasticnet.py`、`patchlib/epoch_trainer_boot_v52.py`、`patchlib/webview_controller.py`、`patchlib/room_manifest.py`、`patchlib/gui.py`、`patchlib/cli.py`。

回帰テスト: `python -m pytest -q tests/test_auto_committee_v88.py tests/test_compact_journal_gc_v88.py tests/test_epoch_trainer_boot_v52.py`。

実機の長時間・多ノードWANテストは未実施。まず小規模の独立3ピア環境で、合意・世代切替・再起動後の重み同一性を確認すること。
