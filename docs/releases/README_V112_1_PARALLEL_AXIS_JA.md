# v112.1 — PT比較グラフの横軸を修正

## 問題点

v112では全条件に同じ総トークン数を与えたのに、全グラフの横軸が総トークン数でした。これは「同じ総計算量でモデル品質を比べる」には有効ですが、理想的に並列動作するピアの作業時間軸を比較できません。

## v112.1

- `pt-heldout-loss.png` / `pt-heldout-accuracy.png`：**各ピアが処理したトークン数**（総トークン数 ÷ ピア数）を横軸として表示。
- `pt-heldout-loss-total-tokens.png` / `pt-heldout-accuracy-total-tokens.png`：従来の**総トークン数**を横軸とした公平な総計算量比較。
- `trace.csv` に `tokens_per_peer`, `steps_per_peer`、`summary.csv` にも同名の列を追加。
- `result.json` に描画軸を明示。

**注意**：各ピアの処理トークン数を横軸にするのは、すべてのピアが同速かつ同時に動くと仮定した「理想並列作業軸」です。これは実測秒数ではありません。通信時間、バリア待ち、ストラグラー、ネットワーク遅延は含めません。`serial_wall_s` はあくまで1台のMacで直列実行した実測秒数であり、ピア数で割るべきではありません。

また、v112の各条件は同じ**総学習量**で終了するため、複数ピアほど短い横軸位置で終わります。同じ理想並列作業時間での品質を公平に比較するには、各ピアに同じローカルステップ数を実行させる「等並列時間予算」の追加実験が必要です。v112.1はその追加実験を実施したものではありません。

既存ルーム・CLI・GUIには変更ありません。
