# KCIA v139 — オンライン通信損益最適化 / WAN Cost Bandit

## 目的

v138 の **モデルのパラメータ数と署名更新サイズに応じた既定送信間隔**を維持しながら、
各ピアのローカル学習中に観測した **Lossの相対的な改善傾向**と**送信量**の費用対効果を
オンラインで更新する。モデルを重くしても署名プロトコルやルームID、ReLoRAの20イベント設定は変更しない。

**重要な制約:** ここでいうLoss改善は *学習ミニバッチ上の代理指標* です。通信の因果効果、
汎化性能、ホールドアウトLossの改善、モデル同士の同期収束を推定したと主張するものではありません。
観測と評価は各ピア固有であり、非IIDの分散データ、SFT/PPO混合によって指標が大きく揺れることがあります。

## 仕組み

- WAN自動調整では既定で `--cost-bandit` が有効になります。手動送信間隔やデバッグモードでは無効。
- モデルサイズから推定した最初の送信間隔を下限とし、近傍を `×2` ずつ最大1024ミニバッチまで探索します。
- イベントにつき8個ずつの先頭・末尾Lossの中央値から、**相対Loss改善/1000ミニバッチ**を推定。
- 署名付き更新バイト数 × 期待送信先数を通信コストの下限とし、前回の区間に観測した非同期の `push + repair` 送信バイト数がそれより大きければそちらを使用。実際の送信は非同期なので、**厳密なイベント別送信量ではなく保守的な近似**です。
- `log2(送信間隔 / 初期値)` の2次項を使った正則化回帰に、探索ボーナス（UCBに類似）を加える。実際の目的関数は `予測された相対Loss改善/1000ミニバッチ − wire_cost × 推定MiB/ミニバッチ − 期限遅延ペナルティ + 探索ボーナス`。
- 新しい観測ほど重くする指数忘却。1サンプルあたり長さ64件まで。行列は3×3のため低オーバーヘッド。モデルテンソルを移動しません。
- 3回以上の有効イベントを観測するまで送信間隔を変えません。再評価は3イベントに1回まで、1回あたり最大2倍（または1/2倍）。小さな利益差では変更しないヒステリシス付き。
- 同じブロックの途中で他ピアからの更新が反映された場合、短い部分イベントや非有限Lossのサンプルは**学習効果の回帰から除外**します。署名更新のバイト数は別に計測できます。
- コスト係数変更時には過去の最適判断を再利用しません。統計はジャーナルに隣接する `*.wan-bandit-v139.json` に小容量かつローカル・0600で原子的に保存。署名ジャーナルには書き込みません。

## GUI

`TRAINING → 送信間隔 → WAN` で使用します。

`通信コスト重み（WAN学習）` の既定値は `0.08`、範囲は `0..10`。
高くすると通信削減を強く優先します。0ならバイト単価は無視します（探索と遅延ペナルティは残ります）。
**`trainBanditStats`** に、有効観測回数、Loss傾向/1000ミニバッチ、推定署名MiB/ミニバッチを表示します。
GUIに保存される係数はピア固有・ローカルのみ。ルーム定義へは含めません。

例（GUIは既定で有効、必要ならCLIでも使用可能）:

```bash
python -m patchlib.cli train-live ... --auto-model-cadence --cost-bandit \
  --bandit-wire-cost 0.08 --bandit-exploration 0.04
```

旧v138のサイズベース固定式へ戻すには `--no-cost-bandit` を指定。
GUIならカスタム（手動）モードを選んでください。

## ログ・テレメトリ

```
KCIA WAN COST BANDIT active base=32 selected=32 trials=0 ...
KCIA WAN BANDIT status steps=... samples=... patch_mib=...
KCIA WAN BANDIT updated_steps=... previous=... trials=...
```

GUIの1秒間隔のテレメトリに追加されるキー:

- `publish_steps` — *実際に次のイベントが要求する間隔*、モデル・メンバー数・バンディットの最大値
- `bandit_trials` — 学習に利用できた有効なサンプル数
- `bandit_gain_per_1000` — 相対Loss減少の学習ミニバッチ傾向（代理指標、負にもなる）
- `bandit_signed_mib_per_step` — 署名されたイベント量と観測通信量による保守的な推定値
- `bandit_net_utility` — 正則化2次回帰で算出された通信費用を引いた代理効用
- `push_mib` / `repair_mib` — 従来からの**実際に送信完了した**累積バイト量

`bandit_*` は個別ピアのローカル観測であり、全ピア平均の汎化評価値ではありません。

## 修正したv138の不整合・堅牢化

- 初期推奨の上限と再推奨の上限が一致していなかった問題を修正（ワーカーの大規模モデル上限を1024へ）。
- 変更済みのコスト係数から誤って前回の選択を引き継がないよう、キャッシュ互換性を検証。
- 強制途中シール/起動後の未完成学習ブロック/非有限Loss/受信更新で汚れたサンプルを回帰対象外に。
- 0/非数/範囲外の損益係数をGUIとCLI両方で検証。
- 既存GUIのネットワーク経路とモデル署名形式を変更せず、モデル選択とルーム状態の不変条件を維持。
