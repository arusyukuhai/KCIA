# KCIA v141 — WAN通信費用の再接続耐性と不要コード整理

v140からの安全性ホットフィックスです。**GUI/WANの既定設定と署名付き通信形式は変更しません**。研究用ソフトウェアであり、Mac/Colab/ConoHaの実WAN長期試験や全テストの完全成功を保証するものではありません。

## 修正した問題

1. **再接続で実測送信量を過少計上**。以前は全RTCノードの累積 `push_sent_wire_bytes + repair_sent_wire_bytes` を単一スカラーで差し引いていました。ピア切断によるノード消滅・再接続によるカウンター初期化のあと、実際に送ったバイトが差分0として扱われることがあります。`WireEgressTracker` を導入し、RTCノードごとに送信/修復のカウンター差分を追跡します。WeakKeyDictionaryを使用し、終了したノードを保持し続けません。既存の `wan-bandit-v139.json` 形式は変更しません。
2. **実配信先と費用予測の不一致**。新しいイベントのPush送信先にも、認証済み・モデル同期済み・生存確認期限内という同一の判定を適用。接続しただけでスナップショット同期待ちのピアへ大型イベントを先行キュー投入しないようにしました。欠落イベントは署名ジャーナルの既存のfrontier/NEED修復で回収します。
3. **8ミニバッチでLoss改善推定が常に0**。前半8点と後半8点が完全一致していました。4～8点の重ならない前半・後半区間を採用。32ステップ以上の通常設定でも、評価窓をデータ件数に合わせて適切に選択します。
4. **不正キャッシュ値の受理**。JSONの浮動小数点型 `32.0` が離散間隔 `32` と同じと判定されて復元される余地があったため、`selected` / `history[].arm` を整数型に限定しました。キャッシュは助言用のローカルファイルであり、署名付き学習ジャーナルを変更しません。
5. **不要コードの整理**。`elasticnet.py` の未使用ローカルimport、`p2p.py`・`shardp2p.py`・`snapshot_live.py`・`expert_runtime.py` の未使用importを削除。配信先判定の重複ロジックを共通関数へ統合しました。

## 意図的に削除しなかったもの

`patchlib` の世代管理、MoE、Critic、SFT/PPO、CLIツールなどは**動的な読み込み・実験用エントリポイント・既存テストから参照される**ため、単にソース内の文字列参照が少ないだけでは削除しません。`wan_state`、`.kcia-gui`、署名鍵、ジャーナル、checkpointなどの実行データは触っていません。GUIのWAN標準ドメインは `kcia.tech`、実接続先は `wss://signal.kcia.tech/ws` のままです。

## 適用

実行中のGUI・ワーカーを終了し、**v140のソース**で以下を実行します。

```bash
cd ~/Documents/GitHub/Fedpara
git apply --check ~/Downloads/KCIA_v141_from_v140_bandit_churn_cleanup.patch
git apply ~/Downloads/KCIA_v141_from_v140_bandit_churn_cleanup.patch
python -m patchlib.cli gui
```

配布ZIPの完全版を使う場合、`wan_state`等の私有状態ディレクトリを上書き・削除しないでください。

## 検証

- v141新規テスト：WebRTC再接続時のカウンター0リセット、弱参照の解放、配信先の一致、8ミニバッチでのLoss変化、不正キャッシュ拒否。
- v139/v140 + Webview/WAN/スナップショット/署名Gossip回帰テスト。
- Python構文検証、JS構文検証、ソース配布に含むべきファイルの監査、v140からのパッチ適用一致チェック。

**残る課題**：通信バイト数はイベント確定タイミングでの観測であり、非同期に遅延して送られる修復データは別のイベント区間に計上され得ます。バンディットのLoss指標は局所的な代理評価であり、通信の因果効果や汎化性能を保証しません。実際のネットワーク帯域、GPU稼働率、学習トークンあたりの総通信バイトを比較しながら検証してください。
