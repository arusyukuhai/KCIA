# KCIA v137 — 安定性・GUI負荷・不要ファイル監査

## 確認された原因と修正

- 同じHFモデル/Revisionの互換性問い合わせがGUI一覧更新で繰り返される。最大128件のメモリキャッシュを設け、同時実行の重複を排除。一覧再取得後も照会結果を再利用。
- 0.9秒ごとのステータス更新で値が変わらなくてもDOMテキストを更新し、最大9種類のSVGグラフを再描画していた。データの変化をチェックして省略。スクロール・履歴切替は明示的に再描画。
- NETWORK図も同じ接続集合に対して全削除していた。ピア集合が変わるまでSVGツリーを再利用。
- 公開WSSの疎通検査とHTTPルーム一覧取得が逐次実行（最大約12秒）。独立検査を同時実行するよう改修。
- グラフテレメトリのJSONLファイルが別inodeへ置換された瞬間に読み出すと一時例外が起き得る。ベストエフォートな空配列で復帰。
- 通信中にネットワークモードの選択肢を切り替えると、バックエンドでは拒否されてもGUIの表示が先に切り替わる。UI側で先に拒否する。
- モデル計画中にユーザーが選択を変えると、古い非同期レスポンスを新しいルームに適用して起動できてしまう競合。応答IDと対象モデルの照合、重複起動防止を追加。
- GUIの古いリリース資料がルートに多重存在し、現行の学習頻度と以前の「4 minibatches」既定値を混同しやすかった。旧リリースノートを1つの履歴に統合。現行READMEを短縮。

## 安全に削除した対象

- 古いルート階層の `README_V119_*` ～ `README_V136_*` （バージョンごとの配布メモ。記録は `docs/releases/RELEASE_HISTORY_PRE_V137.md` に保存）
- GUIで1行しか処理しない不必要な `checkCompatibility` ラッパー、およびRPCタイムアウト条件式の重複。

## 意図的に残したもの

- `patchlib`の版番号付きモジュール、Nimシグナリングの古いHTML、テスト・ベンチマーク用スクリプト。CLIの文字列importや別エントリポイントで使用されている可能性があるため、一律削除しない。
- ルームID・署名鍵・モデル・SQLiteジャーナル・実行時データは触れていない。

## 未検証／残るボトルネック

- 実際のMac/WebKit上のフレーム時間と、ConoHa + Colab上での長時間WAN学習。
- `elasticnet.py`の大規模な非同期状態機械と158 MB級の学習更新。今回は署名・FedSum・通信プロトコルを改変せず、GUIのホットパスを中心に修正。
- 公開ルーム一覧やHugging Faceリポジトリへの外部アクセスはネットワーク状況に依存する。再描画とHTTP照会の負荷を軽減したが到達性の保証はない。

オフライン回帰テストが成功しても実WANのレースコンディションを完全に保証するものではありません。
