# KCIA v138 — モデル規模対応・独立目的関数・ピア独自データセット

v137のWAN GUIを拡張した**研究用実装**です。新しいルームプロトコル、署名形式、既存のジャーナル・Genesisは変更しません。

## 1. モデルが大きくなるほど送信間隔を延ばす

TRAINING > 送信間隔を「WAN · モデル規模と更新サイズで自動調整」に設定します（通常のWAN GUIでは既定）。学習開始時にロードしたモデルのパラメータ数で初期の `local minibatches / signed publish` を見積もり、最初の**実際の署名済み更新**のバイト数で次の送信間隔を補正します。既定の下限32、実測更新サイズからの増加は通常最大512ミニバッチです。大規模モデルのGUI初期推定が512を超えた場合は1024まで選ばれることがあります。増加は学習ローカルのみで、ルームのReLoRAイベント間隔20は変えません。手動モードの値は上書きしません。

例（既定下限32）：135Mモデル・約11MB更新 => 32ミニバッチ。135Mモデル・約158MB更新 => 256ミニバッチ。巨大モデルでは通常最大512（GUI初期推定の超大型モデルは1024）。実際の更新サイズ、GPU/CPU、rankで値が変わります。ネットワークの帯域や遅延を実測する自動帯域制御ではありません。

コンソールには `KCIA WAN AUTO CADENCE parameters=... initial_steps=...`、変更時に `updated_steps=... patch_bytes=...` を表示します。

CLIの `train-live` にも `--auto-model-cadence` を追加しました。従来CLIの既定動作は変更しません。

## 2. 新規モデル作成時のPT・SFT・PPO独立ON/OFF

NEW MODEL > **Training objectives** で PT / SFT / PPO を個別にON/OFFにします。少なくとも1方式が必要です。SFTにはSFT専用の学習データ、PPOにはPPOデータと報酬・Critic設定が必要です。各方式の重みも指定できます。

- PTのみ: 従来どおり
- SFTのみ: PT=OFF, SFT=ON, PPO=OFF
- PPOのみ: PT=OFF, SFT=OFF, PPO=ON
- 任意の混合: ON/OFF と損失重みを個別設定
- **Preference-SFT**: 既存の選好ペア損失をSFTと併用。HFかJSONLの `prompt/response/rejected` 相当列を選択します。**DPOとは別の実装**です。PPOには従来どおりKL自動制御、Entropy bonus等の調整があります。

共有ルームの目的関数・重み・報酬ルールは**署名付きルーム定義で固定**されます。既存ルームで許可されていない学習手法を参加者が勝手に有効化することはできません。別の手法の組み合わせに変更するなら**新規ルームを作成**してください。現行ルームスキーマ上、PT=OFFでも、モデルの学習データ参照メタデータとして基本HFデータセット定義が必要です（PT勾配は計算しません）。

SFT/PPO/Preference-SFTは現在causal-lmモデルに対応します。公開ルーム用SFT/PPO HFソースは40文字のcommit SHAで固定してください。

## 3. 各P2P参加者ごとに独自データセット

1. MODELSで参加する既存ルームを開きます。
2. DATASETS画面で、**この端末のPTに使いたい**HFデータセット・commit SHA・split・列対応を選択します。
3. TRAINING画面で「DATASETSで選んだ内容をこのピアへ適用」を押します。「このピアの独自データセットを使用」になれば反映済みです。
4. 学習開始時にprivate JSONがピア単位で保存され、各端末のPTデータローダーのみが置き換わります。部屋全体の署名済みデータセットやモデルGenesisは不変です。
5. 「ルームの既定データセットを使用」に戻せば、その起動ではルーム既定のPTを使用します。

ソースはHugging Faceの公開/アクセス可能なpin済みリビジョンに限定します。PTの別スキーマは使用できません。ルームがSFT/PPOを許可している場合は、ピア専用のSFT/PPOソースも既存の混合学習設定から変更できます。ただし、**目的関数・報酬定義を変更することはできません**。

**重要**: 変更するのは各ピアのサンプル入力です。生テキストはシグナリングサーバーへ送信せず、ネットワークには署名付き学習更新が流れます。学習対象データに対する配信権・利用規約・プライバシー保護は各ピアの責任です。更新からの情報漏えいリスクがゼロになるわけではありません。

## 4. 更新・検証

起動: `python -m patchlib.cli gui`。既存ソースの改変前にバックアップし、GUIワーカーを停止してください。`wan_state/`、`.kcia-gui/`、鍵、ジャーナル、チェックポイントは削除しません。VPSの再設定は不要です。

```bash
python -m pytest -q tests/test_v138_cadence_objectives.py tests/test_v138_cadence_objectives_sources.py
node --check web/desktop_webview.js
```

今回の検証はローカル単体・回帰テストです。Mac/Colabの実WANでの**モデル規模別GPU利用率・収束率・通信量**は未測定です。また、大型モデルの長時間学習や複数ピアの異種データ分布に対する収束保証はありません。
