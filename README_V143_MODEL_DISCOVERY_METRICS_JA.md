# KCIA v143 — モデル一覧のソートと累計ルーム統計

## 画面（MODELS）

ソートの既定は **人気順**。以下から切替可能、端末ごとに選択を復元します。

- 人気順：`4×log(1+累計参加ピア数) + 2×log(1+累計訓練時間[h]) + 2×オンラインピア数`。
- 累計参加ピア数 / 累計訓練時間 / オンライン / 新しい順 / 古い順 / 名前 / データセット数。

人気スコアは比較・発見のためのヒューリスティックで、モデルの品質や安全性を保証しません。同点の場合オンライン数・作成日時・ルームIDで安定した表示順にします。モデル一覧は表示中に60秒ごとに更新します。公開ルームには、参加ピア数と延べ訓練時間（h）を表示します。

## サーバー側の累計値（更新必要）

`src/main.nim`（Mummyシグナリング）も更新します。古いVPSサーバーのままでは累計統計は生成されず、GUIに「未取得」と表示されます。

- 累計参加ピア数：`group-join` を成功した**異なるピアID**の数。同一IDでの再接続は増やしません。これは人間の人数ではなく、署名ピア識別子の数です。
- 累計訓練時間：各ワーカーが、学習ステップとOptimizer更新の実行区間で計測した経過時間の**全ピア延べ合計**です。ログイン時間、単なる接続時間、SNAPSHOT PRIORITY HOLDの待機時間は加算しません。CPU/GPUカーネル実行時間だけでなく、学習ステップ中の前処理・同期待ち時間なども含みます。2ピアが同時に1時間学習すると約2ピア時間です。
- `training-report` は15秒間隔で接続済みのgroup WebSocketから送信されます。32桁の実行IDと、その実行IDでの累積ミリ秒を送るため、再接続や同じ報告のリトライで二重計上しません。サーバーは当該接続または直前報告から経過した壁時計時間を上回る増分を受け付けません。
- **署名付きの計算時間証明ではありません。** 参加者自身による計測報告です。悪意ある参加者が虚偽のID・訓練時間を送ることへの完全な耐性は未実装です。高信頼なランキングにはチャレンジ署名とレート制限・不正検知が必要です。
- サーバー側で `ROOM_DATA_DIR/_usage/<room_id>.json` に永続化します（個別のimmutable manifestは編集しません）。通常はルームごとに最大60秒に1回書き込み、負荷を抑えます。異常終了の場合、未フラッシュの直近最大約60秒が失われる可能性があります。
- 後方互換性：group-membersが `usage_v1:true` を通知した場合だけクライアントが訓練時間報告を開始します。古いサーバーへ余計なメッセージを送信しません。旧版での訓練・参加履歴を新たに遡及して復元することはできません。
- メモリ上の管理は1ルームにつき最大65,536ユニークピアIDと65,536学習実行IDです。それを超える大規模な本番環境では外部DB等への置き換えが必要です。

## 導入順序

1. **VPSシグナリング**：`src/main.nim` を含むv143のソースをConoHa側へ配置（秘密情報 `.env` や既存Docker volume `rooms` は保持）し、リポジトリルートで次を実行します。

   ```bash
   docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yml up -d --build signal
   docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yml logs --tail=50 signal
   ```

   現在のcoturn・Cloudflare Tunnelのサービスを無理に再作成する必要はありません。**Nimコンパイルが成功したこと、既存の`/api/rooms`が引き続き返ることを確認してから展開してください。** 既存の `rooms` volume は破棄しないでください。

2. **Mac / Colab / GUI**：v143のクライアントコードへ更新。`python -m patchlib.cli gui` でGUIを起動し、MODELSの人気順・累計統計を確認してください。従来の署名鍵、`wan_state`、`.kcia-gui` は消去しません。

## 検証上の制限

Python統計・GUIソート関連テストは実施済みです。今回の実行環境にはNimコンパイラもVPSへの操作権限もないため、**Nimの実コンパイル・ConoHaへの実デプロイ・実WANでの統計更新は未検証**です。公開前に上記シグナリングのビルドと実機通信・再接続をテストしてください。
